TCP (Transmission Control Protocol): how it works, step by step

TCP provides reliable, ordered, congestion-controlled byte-stream delivery over unreliable IP networks using sequence numbers, acknowledgments, sliding windows, and adaptive congestion control.

TCP explained simply

TCP is like a registered phone call: first both say "Can you hear me? / Yes, can you hear me? / Yes!" then number every sentence and repeat any part that broke up.

How TCP works, step by step

  1. 3-Way Handshake

    SYN -> SYN-ACK -> ACK (Seq/Ack sync). Client and Server exchange initial sequence numbers (ISN) and negotiate MSS=1460.

  2. Slow Start

    cwnd grows exponentially (2 -> 4 -> 8 MSS). Congestion window doubles each RTT while cwnd < ssthresh.

  3. Loss & Recovery

    Segment loss triggers Reno/CUBIC backoff. Simulated loss or congestion reduces ssthresh and triggers fast retransmit / RTO recovery.

  4. Congestion Avoidance

    Linear AIMD growth after ssthresh. TCP probes bandwidth cautiously (+1 MSS per RTT) to avoid saturating queues.

  5. 4-Way Teardown

    FIN-ACK -> FIN-ACK -> TIME_WAIT. Both sides cleanly close their half-duplex byte streams with FIN and final ACK.

TCP security notes

  • SYN Flood DoS. Attackers send millions of forged SYN packets without completing the handshake, exhausting the server’s SYN_RCVD backlog. Defense: Enable SYN Cookies so the server encodes state into the ISN instead of allocating memory.
  • TCP RST Injection. On-path or blind attackers inject forged RST segments matching the 4-tuple and sequence window to kill connections. Defense: Encrypt sessions with TLS or IPsec and use strict RFC 5961 challenge ACKs.

Test yourself on TCP

Which flags are set in the second packet of a TCP 3-way handshake?

Answer: SYN and ACK. The server replies with SYN+ACK to acknowledge the client’s SYN and send its own ISN.

What triggers TCP Fast Retransmit without waiting for RTO expiration?

Answer: 3 duplicate ACKs. Receiving 3 duplicate ACKs signals an out-of-order gap and triggers immediate retransmission.

During TCP Slow Start, how does cwnd grow per RTT when no packets are lost?

Answer: Exponentially (doubles). Every ACK increases cwnd by 1 MSS, doubling cwnd each round-trip time until ssthresh.

Why does the active closer enter TIME_WAIT after sending the final ACK?

Answer: To allow delayed packets to drain and ensure the peer received the final ACK. TIME_WAIT (2*MSL) prevents old delayed segments from corrupting a new connection on the same 4-tuple.

Which defense mitigates SYN flood memory exhaustion?

Answer: SYN Cookies. SYN cookies avoid storing half-open state until the client returns the third handshake ACK.
