UDP (User Datagram Protocol): how it works, step by step

What is UDP?

UDP is a lightweight, connectionless transport protocol with an 8-byte header and zero handshake or retransmission overhead, ideal for real-time audio/video, DNS, and QUIC.

What is UDP, in simple words?

UDP is like tossing postcards into a mailbox as fast as you can: no phone call first, no waiting for receipts—fast and lightweight, even if one card blows away in the wind.

How does UDP work, step by step?

  1. Zero-Handshake Send

    Immediate datagram emission (8B header). Application hands data to UDP; no SYN handshake occurs—datagram #1 leaves immediately.

  2. Independent Datagrams

    Datagrams #2 & #3 travel without ACK blocking. Each datagram is self-contained; packet loss does not stall later packets (no head-of-line blocking).

  3. App-Level Handling

    Receiver processes arriving datagrams. Receiver reads datagrams from socket buffer; optional app-level sequence checks handle loss.

Is UDP secure? Common attacks and defenses

  • UDP Amplification DDoS. Because UDP has no handshake, attackers spoof the victim’s source IP to trigger huge replies from DNS/NTP/Memcached. Defense: Enforce BCP 38 source-address validation and disable open unauthenticated UDP reflectors.

Frequently asked questions about UDP

How large is a standard UDP header?

Answer: 8 bytes. UDP headers contain just 4 two-byte fields: Src Port, Dst Port, Length, and Checksum (8 bytes).

Why do online games and VoIP prefer UDP over TCP?

Answer: UDP avoids handshake and retransmission head-of-line delays. Real-time voice/gaming prefers dropping a stale frame over stalling new frames for TCP retransmissions.

What IP protocol number identifies UDP?

Answer: 17. IPv4 Protocol field 17 indicates UDP.
