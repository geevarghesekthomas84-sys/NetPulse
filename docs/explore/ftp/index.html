FTP (File Transfer Protocol (Active & Passive)): how it works, step by step

FTP uses two separate TCP connections: a Control channel on port 21 for commands, and a Data channel for file transfers. Passive mode (PASV) lets clients behind NAT initiate the data connection.

FTP explained simply

FTP uses two walkie-talkies: one channel (#21) just for saying "Send file report.pdf", and a second cargo pipe where the file bytes actually travel.

Devices in the FTP exchange

  • Client (host, 192.168.1.10)
  • Firewall (NAT) (firewall, 192.168.1.1)
  • File Server (file server, 203.0.113.20)

How FTP works, step by step

  1. Control Channel (Port 21)

    USER / PASS login on TCP 21. Client opens TCP control channel to port 21 and authenticates.

  2. PASV Negotiation

    Server opens ephemeral data port (e.g. 50120). In Passive mode, server tells NAT-behind client which data port to connect to.

  3. Data Channel Transfer (RETR)

    Second TCP socket transfers file bytes. Client connects to port 50120; RETR downloads file and closes data socket.

FTP security notes

  • Plaintext Credentials & Data Sniffing. Standard FTP sends usernames, passwords, and file contents unencrypted. Defense: Replace plain FTP with SFTP (over SSH port 22) or FTPS (TLS).

Test yourself on FTP

Why does FTP use Passive (PASV) mode behind home/office NAT firewalls?

Answer: Because Active mode requires the server to open a connection back to the client through NAT. In PASV mode, the client initiates both control and data TCP connections outbound.

Which ports are used by standard FTP control and active data?

Answer: 21 (Control) and 20 (Active Data). Port 21 is control; port 20 is the server source port for active data transfers.

Which secure alternative runs over SSH port 22 instead of FTP?

Answer: SFTP. SFTP runs over a single encrypted SSH connection on port 22.
