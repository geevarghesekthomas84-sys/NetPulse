SSH (Secure Shell Protocol (SSH-2)): how it works, step by step

SSH establishes an encrypted, mutually authenticated channel over untrusted networks for remote shell access, SFTP file transfer, and port tunneling.

SSH explained simply

SSH is like opening an armored, soundproof tunnel to a distant server where you prove who you are with an unforgeable cryptographic key instead of shouting passwords across the street.

How SSH works, step by step

  1. TCP + Version Exchange

    SSH-2.0 banner exchange on port 22. After TCP handshake, both peers send plaintext SSH-2.0 protocol identification banners.

  2. KEXINIT & Curve25519 ECDH

    Diffie-Hellman key exchange + host key verify. Client and server negotiate encryption algorithms and derive shared session keys via Curve25519.

  3. User Authentication

    Ed25519 public-key signature (or password). Encrypted auth request signs a challenge with the user’s Ed25519 private key.

  4. Interactive Shell Channel

    Multiplexed encrypted PTY / SFTP. Client opens session channel, allocates PTY, and runs shell commands over ChaCha20-Poly1305.

  3. SSH from 192.168.1.10 to 10.0.0.20: Client: Protocol (SSH-2.0-gg_ssh) (90 bytes)
  4. SSH from 192.168.1.10 to 10.0.0.20: SSH_MSG_KEXINIT + Curve25519 ECDH Init (720 bytes)
  5. SSH from 10.0.0.20 to 192.168.1.10: KEX_ECDH_REPLY (Host Key) + NEWKEYS (840 bytes)
  6. SSH from 192.168.1.10 to 10.0.0.20: Encrypted USERAUTH_REQUEST (publickey ssh-ed25519) (210 bytes)
  7. SSH from 10.0.0.20 to 192.168.1.10: SSH_MSG_USERAUTH_SUCCESS (88 bytes)
  8. SSH from 192.168.1.10 to 10.0.0.20: CHANNEL_OPEN (session) + Encrypted Shell Command (164 bytes)

SSH security notes

  • Brute-Force Password Guessing. Automated bots scan port 22 trying thousands of common username/password pairs. Defense: Disable PasswordAuthentication, require Ed25519 public keys, and rate-limit with fail2ban/MFA.

Test yourself on SSH

Which default TCP port does SSH listen on?

Answer: 22. SSH uses TCP port 22 (replacing insecure Telnet on port 23).

Why does SSH warn on first connection about an unknown host key fingerprint?

Answer: To verify you are connecting to the genuine server and not a MITM proxy. Checking the server’s host key fingerprint (TOFU/known_hosts) prevents man-in-the-middle interception.

Which authentication method is strongly recommended over passwords for SSH?

Answer: Public-key authentication (e.g., Ed25519). Ed25519/RSA keypairs resist password brute-forcing and never transmit secrets.

Which file-transfer protocol runs natively inside an SSH channel?

Answer: SFTP. SFTP runs as a subsystem over an encrypted SSH channel on port 22.

What happens during the SSH KEX_ECDH phase?

Answer: Peers derive shared symmetric session keys using Diffie-Hellman. ECDH key exchange establishes ephemeral symmetric keys for the rest of the session.
