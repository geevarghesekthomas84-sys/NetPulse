TLS / SSL (Transport Layer Security (TLS 1.3)): how it works, step by step

What is TLS / SSL?

TLS 1.3 provides confidentiality, integrity, and server authentication in a single 1-RTT handshake using ephemeral Diffie-Hellman (ECDHE) for forward secrecy and AEAD ciphers.

What is TLS / SSL, in simple words?

Before whispering secrets, you and the server publicly mix paint colors (key exchange) to create a shared secret key nobody watching can unmix, then verify their ID badge (certificate).

How does TLS / SSL work, step by step?

  1. TCP Handshake

    SYN / SYN-ACK / ACK on port 443. Client opens a TCP connection to port 443 before starting TLS.

  2. ClientHello (TLS 1.3)

    Supported ciphers, SNI, X25519 key share. Client sends ClientHello with TLS 1.3 cipher suites, SNI=example.com, and ephemeral ECDHE key share.

  3. ServerHello + Certificate

    1-RTT ServerHello, EncryptedExtensions, Cert, Finished. Server derives handshake keys immediately, sends its X25519 share, encrypted certificate chain, and Finished.

  4. Client Finished & App Data

    Encrypted AEAD Application Data (0x17). Client verifies certificate signature, sends Finished, and streams encrypted HTTP Application Data.

Is TLS / SSL secure? Common attacks and defenses

  • TLS Downgrade / POODLE / BEAST. An active MITM forces peers back to obsolete SSL 3.0 or TLS 1.0 ciphers with padding oracle flaws. Defense: Disable SSL/TLS < 1.2 and rely on TLS 1.3 downgrade sentinel inside ServerHello.random.
  • Forged / Untrusted Certificate MITM. A rogue proxy presents an expired or self-signed certificate. Defense: Strictly verify X.509 chain, expiry, SAN hostname, OCSP stapling, and Certificate Transparency.

Frequently asked questions about TLS / SSL

How many round-trips (RTTs) does a standard TLS 1.3 handshake add after TCP connects?

Answer: 1 RTT. TLS 1.3 cuts handshake latency from 2 RTTs (TLS 1.2) down to 1 RTT by sending key shares in ClientHello.

Why are certificates encrypted in TLS 1.3?

Answer: To prevent passive observers from seeing server identity/metadata. After ServerHello, TLS 1.3 encrypts the Certificate and CertificateVerify messages with the handshake key.

What property guarantees past recorded traffic cannot be decrypted even if the server’s long-term private key leaks later?

Answer: Forward Secrecy (ECDHE). Ephemeral Diffie-Hellman keys are discarded after each session, providing Perfect Forward Secrecy.

Which TLS extension tells the server which hostname the client wants when multiple sites share one IP?

Answer: SNI (Server Name Indication). SNI sends the target hostname in ClientHello so the server picks the right certificate.

What happens if the server presents an expired X.509 certificate?

Answer: Client sends a Fatal Alert (certificate_expired) and closes the connection. Clients abort the TLS handshake with Alert level=Fatal, description=certificate_expired.
