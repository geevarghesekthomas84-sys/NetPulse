DNS over HTTPS (DNS Queries over HTTPS (DoH)): how it works, step by step

What is DNS over HTTPS?

DNS over HTTPS (DoH) wraps binary DNS queries inside standard HTTPS port-443 traffic so ISPs and local Wi-Fi observers cannot snoop or tamper with the websites you look up.

What is DNS over HTTPS, in simple words?

Regular DNS is shouting the website name out loud to the phonebook operator. DoH puts that question inside an encrypted HTTPS envelope indistinguishable from normal web browsing.

  • Browser (host, 192.168.1.10)
  • ISP Router (router, 100.64.0.1)
  • DoH Resolver (dns server, 1.1.1.1)

How does DNS over HTTPS work, step by step?

  1. TLS 1.3 Session to Port 443

    Handshake with 1.1.1.1:443. Browser opens an HTTPS/TLS 1.3 tunnel to Cloudflare/Google DoH endpoint.

  2. HTTPS POST /dns-query

    Encrypted wire-format DNS query. ISP sees only opaque TLS packets on port 443—domain name is completely hidden.

  3. Encrypted DNS Response

    200 OK application/dns-message. DoH server returns signed/resolved A record inside encrypted HTTPS 200 OK.

Is DNS over HTTPS secure? Common attacks and defenses

  • Corporate Visibility Bypass. Because DoH blends into TCP/443 HTTPS, enterprise DNS firewalls cannot filter malicious domains unless configured. Defense: Use managed enterprise DoH policies or TLS-aware DNS proxies.

Frequently asked questions about DNS over HTTPS

Which port does DNS over HTTPS (DoH) use?

Answer: 443. DoH uses standard HTTPS port 443 (whereas DNS over TLS / DoT uses port 853).

What Content-Type carries binary DNS wire messages in DoH?

Answer: application/dns-message. RFC 8484 specifies `application/dns-message`.

What privacy threat does DoH eliminate on public Wi-Fi?

Answer: Passive sniffing and injection of plaintext UDP/53 DNS queries. Encrypting DNS prevents local attackers or ISPs from reading or forging DNS replies.
