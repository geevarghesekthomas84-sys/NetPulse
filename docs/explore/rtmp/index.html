RTMP (Real-Time Messaging Protocol (Live Ingest)): how it works, step by step

What is RTMP?

RTMP is the persistent TCP-based ingest protocol used by OBS Studio and encoders to push low-latency live audio/video streams to ingest servers (port 1935) before HLS/DASH distribution.

How does RTMP work, step by step?

  1. C0/C1/C2 + S0/S1/S2 Handshake

    Fixed-size binary handshake on TCP 1935. Encoder and Ingest Server exchange random 1536-byte C1/S1 blocks to sync timestamps.

  2. connect & publish

    AMF0 NetConnection.connect + publish(streamKey). Encoder authenticates with stream key and requests publish rights.

  3. Multiplexed Media Chunks

    H.264 video & AAC audio chunks. Audio, video, and metadata packets are interleaved into 128-byte/4KB RTMP chunks.

Is RTMP secure? Common attacks and defenses

  • Stream Key Exposure on Plain RTMP. Plain RTMP sends the broadcast stream key over TCP 1935 without encryption. Defense: Always stream over RTMPS (RTMP inside TLS) and rotate stream keys.

Frequently asked questions about RTMP

Which TCP port is the standard for RTMP ingest?

Answer: 1935. RTMP uses TCP port 1935 (or 443 for RTMPS).

Where is RTMP primarily used today?

Answer: Live video ingest from encoders (OBS) to streaming platforms. Encoders push via RTMP/RTMPS while viewers usually watch via HLS/DASH/WebRTC.

How do you encrypt RTMP stream keys in transit?

Answer: Use RTMPS (RTMP over TLS). RTMPS wraps the RTMP session inside TLS.

Which protocols are related to RTMP?

  • HTTP: Hypertext Transfer Protocol
  • HTTPS: HTTP over TLS (Secure Hypertext Transfer Protocol)
  • WebSocket: The WebSocket Protocol (WS / WSS)
  • WebRTC: Web Real-Time Communication (ICE / STUN / DTLS / SRTP)
  • SIP: Session Initiation Protocol (VoIP Signaling)
  • RTSP: Real Time Streaming Protocol (CCTV / IP Cameras)
