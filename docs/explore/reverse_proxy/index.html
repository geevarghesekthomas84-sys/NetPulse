Reverse Proxy (Reverse Proxy & Load Balancer (TLS Termination)): how it works, step by step

A reverse proxy sits in front of origin backend servers to terminate TLS, enforce WAF rules, cache static content, and load-balance requests across healthy upstream workers.

Open the interactive Reverse Proxy animation to watch each packet move and inspect its headers.

Reverse Proxy explained simply

A restaurant host greets guests at the front door, checks reservations (WAF), and seats each party at whichever open kitchen table (backend server) isn’t busy.

Data formatHTTP/2 Front-End -> Internal HTTP/1.1 + X-Forwarded-*

Specifications: RFC 7239: Forwarded HTTP Extension.

Devices in the Reverse Proxy exchange

  • Browser Client (host, 192.168.1.10)
  • Reverse Proxy / LB (reverse proxy, 203.0.113.10)
  • Backend Pool #1 (server tower, 10.0.0.21)
  • Backend Pool #2 (server tower, 10.0.0.22)

How Reverse Proxy works, step by step

  1. Health Checks

    LB probes /healthz on Backends #1 & #2. Reverse proxy runs periodic health probes to track healthy pool members.

  2. Client TLS Termination

    HTTPS terminates at edge Reverse Proxy. Client completes TLS 1.3 handshake with the edge Reverse Proxy.

  3. Upstream Routing & LB

    Proxy forwards to Backend #1 (or #2 on failover). Reverse proxy injects X-Forwarded-For and balances across healthy backends.

Reverse Proxy security notes

  • X-Forwarded-For Spoofing. If the proxy trusts client-supplied X-Forwarded-For headers blindly, attackers can bypass IP allowlists. Defense: Strip/overwrite X-Forwarded-For at the edge reverse proxy before forwarding upstream.

Test yourself on Reverse Proxy

What is the key difference between a forward proxy and a reverse proxy?

Answer: Forward acts on behalf of clients; reverse acts in front of origin servers. Forward proxies shield/govern clients; reverse proxies shield/scale backend servers.

Which HTTP header preserves the original client IP behind a reverse proxy?

Answer: X-Forwarded-For / Forwarded. X-Forwarded-For (or RFC 7239 Forwarded) records the originating client IP.

What is TLS termination at a load balancer?

Answer: Decrypting TLS at the edge proxy so backends receive plain or re-encrypted internal HTTP. TLS termination offloads CPU-heavy crypto from app servers and allows L7 inspection/routing.
