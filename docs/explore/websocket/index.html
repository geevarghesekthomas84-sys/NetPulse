WebSocket (The WebSocket Protocol (WS / WSS)): how it works, step by step

What is WebSocket?

WebSocket upgrades a standard HTTP/1.1 TCP connection into a persistent, full-duplex, low-overhead bidirectional message channel for live chat, trading feeds, and multiplayer games.

What is WebSocket, in simple words?

Instead of mailing letters back and forth every second (HTTP polling), WebSocket knocks once via HTTP ("Upgrade?") and leaves the walkie-talkie channel open both ways.

How does WebSocket work, step by step?

  1. HTTP Upgrade Request

    Upgrade: websocket + Sec-WebSocket-Key. Client sends HTTP GET with Connection: Upgrade and a random base64 Sec-WebSocket-Key.

  2. 101 Switching Protocols

    Server computes Sec-WebSocket-Accept. Server hashes key + GUID, responds HTTP/1.1 101 Switching Protocols, switching socket framing.

  3. Full-Duplex Frames

    Server pushes frames without client polling. Tiny 2–6 byte framed messages flow bidirectionally; client frames are XOR-masked.

Is WebSocket secure? Common attacks and defenses

  • Cross-Site WebSocket Hijacking (CSWSH). Browsers send cookies on WS upgrade; servers that skip Origin checks can be hijacked. Defense: Validate the HTTP Origin header and use WSS (TLS) with CSRF tokens.

Frequently asked questions about WebSocket

Which HTTP status code confirms a successful WebSocket handshake?

Answer: 101 Switching Protocols. 101 Switching Protocols transitions the TCP socket from HTTP to WebSocket framing.

Why must WebSocket frames sent from a browser client be masked?

Answer: To prevent cache poisoning of legacy transparent HTTP proxies. Client-to-server XOR masking stops malicious scripts from crafting fake HTTP requests inside WebSocket frames.

Which heartbeat opcodes keep idle WebSocket connections alive?

Answer: Ping (0x9) and Pong (0xA). WebSocket includes native Ping and Pong control frames.
