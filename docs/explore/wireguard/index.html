WireGuard (WireGuard Modern Cryptographic VPN): how it works, step by step

WireGuard is a lean, kernel-space Layer 3 VPN tunnel running over UDP/51820 using Curve25519, ChaCha20-Poly1305, and BLAKE2s with a single 1-RTT Noise handshake and silent stealth drop on unauthenticated packets.

WireGuard explained simply

WireGuard puts your entire private office envelope inside an unbreakable outer armored pouch addressed between two VPN gateways—outsiders only see scrambled UDP envelopes.

Devices in the WireGuard exchange

  • VPN Gateway A (vpn gateway, 198.51.100.1)
  • VPN Gateway B (vpn gateway, 203.0.113.1)
  • Office B Server (file server, 10.2.0.20)

How WireGuard works, step by step

  1. 1-RTT Noise_IK Handshake

    Initiation + Response over UDP/51820. Gateway A authenticates with Curve25519 static/ephemeral keys in a single round-trip.

  2. Outer IP + ChaCha20 Encapsulation

    10.1.0.10 -> 10.2.0.20 encrypted inside 198.51.100.1 -> 203.0.113.1. Inner LAN packet is encrypted with ChaCha20-Poly1305 and sent as an outer UDP/51820 datagram.

  3. Decapsulation at Office B

    Cryptokey routing verifies AllowedIPs -> LAN B. Gateway B decrypts, verifies AllowedIPs includes 10.1.0.10, and forwards to Office B Server.

WireGuard security notes

  • Static IP Correlation / Metadata. WireGuard assigns static internal tunnel IPs mapped to peer public keys. Defense: Use ephemeral peer keys or MASQUE/relay proxies when anonymity from endpoints is required.

Test yourself on WireGuard

Which transport protocol and default port does WireGuard use?

Answer: UDP 51820. WireGuard runs over UDP (default port 51820) avoiding TCP-over-TCP meltdown.

Which AEAD cipher does WireGuard use for all encrypted tunnel data?

Answer: ChaCha20-Poly1305. WireGuard uses a fixed modern suite: Curve25519, ChaCha20-Poly1305, BLAKE2s, SipHash24.

How does WireGuard respond to an unauthenticated packet from an unknown peer?

Answer: Drops it silently (stealth). Silent drop makes WireGuard invisible to unauthenticated port scanners.
