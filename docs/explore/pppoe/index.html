PPPoE (Point-to-Point Protocol over Ethernet): how it works, step by step

PPPoE lets ISPs authenticate broadband subscribers (DSL/FTTH) and assign public IPv4 addresses over Ethernet using a 4-step Discovery phase (PADI/PADO/PADR/PADS) followed by PPP LCP, CHAP auth, and IPCP.

Open the interactive PPPoE animation to watch each packet move and inspect its headers.

PPPoE explained simply

When your home router plugs into a fiber ISP line, PPPoE rings the ISP’s front desk (PADI/PADO), logs in with your ISP username/password (CHAP), and gets your public internet IP.

Specifications: RFC 2516: A Method for Transmitting PPP Over Ethernet (PPPoE).

Devices in the PPPoE exchange

  • Home Router (router, 0.0.0.0)
  • Access Concentrator (switch, 198.51.100.1)
  • ISP BRAS / Access Server (server rack, 198.51.100.10)

How PPPoE works, step by step

  1. PPPoE Discovery (PADI / PADO)

    Broadcast discovery -> BRAS offer. Home Router broadcasts PADI (0x8863); ISP Access Server replies with PADO.

  2. Session Confirmed (PADR / PADS)

    Assign Session ID (e.g. 0x04a1). Router sends PADR; BRAS assigns Session ID in PADS.

  3. PPP LCP + CHAP + IPCP

    Authenticate & receive public IP (MTU 1492). Peers negotiate MTU 1492, verify CHAP hash, and IPCP assigns public IP 203.0.113.45.

What PPPoE looks like on the wire

This is the packet sequence NetPulse replays for a typical PPPoE exchange. Open the animation to inspect each one.

  1. PPPoED from 0.0.0.0 to 198.51.100.10: PADI (Active Discovery Initiation - Broadcast) (60 bytes)
  2. PPPoED from 198.51.100.10 to 0.0.0.0: PADO (Active Discovery Offer: AC-Name="ISP-BRAS") (78 bytes)
  3. PPPoED from 0.0.0.0 to 198.51.100.10: PADR (Request) -> PADS (Session ID=0x04a1) (74 bytes)
  4. PPP CHAP from 198.51.100.10 to 0.0.0.0: CHAP Success + IPCP Assigned IP 203.0.113.45 (MTU 1492) (96 bytes)

PPPoE security notes

  • PAP Cleartext Auth & MTU 1492 Blackhole. Legacy PAP sends passwords in plaintext; PPPoE adds an 8-byte header shrinking Ethernet MTU from 1500 to 1492. Defense: Use CHAP authentication and enable TCP MSS Clamping (1452) on home routers.

Test yourself on PPPoE

Why is standard PPPoE MTU 1492 bytes instead of 1500 bytes?

Answer: The PPP + PPPoE header consumes 8 bytes inside the 1500B Ethernet frame. 6B PPPoE header + 2B PPP protocol ID = 8 bytes overhead (1500 - 8 = 1492).

What are the four PPPoE Discovery packets in order?

Answer: PADI, PADO, PADR, PADS. PADI -> PADO -> PADR -> PADS establishes the PPPoE Session ID.

Which PPP sub-protocol assigns the subscriber’s IPv4 address and DNS servers?

Answer: IPCP. IP Control Protocol (IPCP) negotiates IPv4 configuration after authentication.
