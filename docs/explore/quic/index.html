QUIC (HTTP/3) (QUIC Transport & HTTP/3): how it works, step by step

QUIC reimagines transport over UDP port 443 with TLS 1.3 baked in from packet #1 (1-RTT or 0-RTT resume), independent streams that eliminate TCP head-of-line blocking, and Connection IDs that survive Wi-Fi-to-5G handoffs.

QUIC (HTTP/3) explained simply

TCP puts every webpage item on one single-lane train track—if one boxcar stalls, all cars behind it wait. QUIC gives each item its own fast lane over UDP with built-in encryption.

QUIC (HTTP/3) at a glance

OSI layerLayer 4–6 (UDP-based Encrypted Multiplexed Transport)
Default port443 (UDP)
TransportUDP + Built-in TLS 1.3
Data formatEncrypted QUIC Packets + Independent Multiplexed Streams
Common methodsInitial (TLS ClientHello), 0-RTT Early Data, Handshake, 1-RTT Streams, Connection Migration

Specifications: RFC 9000: QUIC: A UDP-Based Multiplexed and Secure Transport; RFC 9114: HTTP/3.

Devices in the QUIC (HTTP/3) exchange

  • Client (host, 192.168.1.10)
  • Gateway (router, 192.168.1.1)
  • Service Server (server rack, 203.0.113.10)

How QUIC (HTTP/3) works, step by step

  1. 1-RTT Initial (Transport + TLS)

    Single Initial packet carries TLS ClientHello. Client sends a 1200B UDP/443 Initial packet combining transport setup and TLS 1.3 ClientHello.

  2. Server Initial + Handshake

    ServerHello + Encrypted Cert in same flight. Server replies with Initial + Handshake packets; connection is ready in 1 RTT total!

  3. Independent HTTP/3 Streams

    Stream 0 (HTML) & Stream 4 (CSS) without HoL blocking. Loss on Stream 0 only pauses Stream 0; Stream 4 delivers CSS immediately.

  2. QUIC from 203.0.113.10 to 192.168.1.10: Initial + Handshake (ServerHello, Cert, Finished) (1320 bytes)
  3. HTTP/3 from 192.168.1.10 to 203.0.113.10: 1-RTT Stream 0 (GET /) + Stream 4 (GET /app.css) (340 bytes)
  4. HTTP/3 from 203.0.113.10 to 192.168.1.10: 1-RTT Stream 0 (200 OK HTML) + Stream 4 (CSS) (1280 bytes)

QUIC (HTTP/3) security notes

  • QUIC Initial Amplification / 0-RTT Replay. Without care, 0-RTT early data can be replayed across servers. Defense: QUIC requires Initial packets >=1200 bytes to thwart amplification and restricts 0-RTT to idempotent GET requests.

Test yourself on QUIC (HTTP/3)

Which Layer 4 protocol does QUIC run on top of?

Answer: UDP (port 443). QUIC runs over UDP so middleboxes don’t break new transport extensions and to eliminate TCP HoL blocking.

How does QUIC keep a session alive when a phone switches from Wi-Fi to 5G?

Answer: Using a 64-bit Connection ID independent of IP/port. QUIC identifies connections by Connection ID rather than the 4-tuple IP/port.

What problem in HTTP/2 over TCP does HTTP/3 over QUIC solve?

Answer: Transport-layer Head-of-Line (HoL) blocking. In QUIC, packet loss only affects the stream carrying that lost frame, not other multiplexed streams.
