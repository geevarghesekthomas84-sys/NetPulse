IPsec (Internet Protocol Security (IKEv2 + ESP)): how it works, step by step

IPsec secures IP traffic at Layer 3 using IKEv2 (UDP 500/4500) to negotiate Security Associations (SAs) and ESP (IP protocol 50) to encrypt and authenticate entire IP packets in Tunnel Mode.

Open the interactive IPsec animation to watch each packet move and inspect its headers.

IPsec explained simply

IPsec is the classic corporate armored truck system: two gateways first sign contracts (IKEv2), then wrap entire internal packets inside an ESP armored outer envelope.

IPsec at a glance

OSI layerLayer 3 (Network)
Default port500 (IKE), 4500 (NAT-T)
TransportUDP (IKEv2) + IP Proto 50 (ESP)
Data formatIKEv2 SA Payloads + ESP Tunnel Header (SPI, Seq, IV, AEAD)
Common methodsIKE_SA_INIT, IKE_AUTH, ESP Tunnel Mode, AH Transport

Specifications: RFC 7296: Internet Key Exchange Protocol Version 2 (IKEv2); RFC 4303: IP Encapsulating Security Payload (ESP).

Devices in the IPsec exchange

  • Office A Host (host, 10.1.0.10)
  • VPN Gateway A (vpn gateway, 198.51.100.1)
  • VPN Gateway B (vpn gateway, 203.0.113.1)
  • Office B Server (file server, 10.2.0.20)

How IPsec works, step by step

  1. IKE_SA_INIT (UDP/500)

    Negotiate Diffie-Hellman & crypto suite. VPN gateways negotiate IKE Security Association parameters over UDP port 500.

  2. IKE_AUTH (UDP/4500 NAT-T)

    Authenticate peers & create Child ESP SA. Gateways verify certificates/PSK and install inbound/outbound ESP SPI keys.

  3. ESP Tunnel Encapsulation

    IP Proto 50 encrypts inner IP packet. Inner packet (10.1.0.10 -> 10.2.0.20) is encrypted and wrapped with a new outer IP header.

  2. IKEv2 from 203.0.113.1 to 198.51.100.1: IKE_SA_INIT Response (320 bytes)
  3. IKEv2 from 198.51.100.1 to 203.0.113.1: IKE_AUTH (Cert/PSK + Child SA 10.1.0.0/24 <-> 10.2.0.0/24) (420 bytes)
  4. IKEv2 from 203.0.113.1 to 198.51.100.1: IKE_AUTH Response (Child SA Established, SPI=0x9a41) (380 bytes)
  5. ESP from 198.51.100.1 to 203.0.113.1: ESP (SPI=0x9a41, Seq=1) [Encrypted 10.1.0.10 -> 10.2.0.20] (296 bytes)
  6. TCP from 203.0.113.1 to 10.2.0.20: Decrypted Inner Packet -> 10.2.0.20 (220 bytes)

IPsec security notes

  • IKEv1 Aggressive Mode PSK Cracking. Weak pre-shared keys in legacy IKEv1 aggressive mode expose hashes to offline brute force. Defense: Use IKEv2 with X.509 certificates or high-entropy keys and AES-GCM.

Test yourself on IPsec

Which UDP ports are used by IKEv2 and NAT Traversal?

Answer: 500 and 4500. IKE uses UDP 500 and switches to UDP 4500 when NAT-Traversal is detected.

Which IPsec sub-protocol provides both confidentiality (encryption) and integrity?

Answer: ESP (Encapsulating Security Payload). AH only authenticates headers; ESP provides encryption + authentication.

In ESP Tunnel Mode, what gets encrypted?

Answer: The entire original inner IP packet (header + payload). Tunnel Mode wraps and encrypts the full original IP packet inside a new outer IP header.
