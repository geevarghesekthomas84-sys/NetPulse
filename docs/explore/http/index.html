HTTP (Hypertext Transfer Protocol): how it works, step by step

HTTP is the stateless request-response protocol that powers the World Wide Web. A client opens a TCP connection (after DNS resolution), sends a structured method and headers, and receives status codes, headers, and a payload.

Open the interactive HTTP animation to watch each packet move and inspect its headers.

HTTP explained simply

Imagine mailing a postcard saying "Please send me page 1 of your menu" (GET /), and the restaurant mails back the menu printed on paper anyone along the route could read.

Devices in the HTTP exchange

  • Client (host, 192.168.1.10)
  • DNS Resolver (dns server, 8.8.8.8)
  • Root DNS (dns server, 198.41.0.4)
  • .com TLD (dns server, 192.5.6.30)
  • Authoritative (dns server, 198.51.100.53)
  • Web Server (web server, 203.0.113.10)

How HTTP works, step by step

  1. Client Request

    Browser parses URL & builds HTTP GET. Browser parses http://www.example.com/ and prepares a GET request before resolving the hostname.

  2. DNS Resolution

    Recursive lookup: Resolver -> Root -> .com TLD -> Auth. Stub resolver queries 8.8.8.8, which walks the DNS hierarchy to resolve www.example.com to 203.0.113.10.

  3. TCP Connection

    3-Way Handshake (SYN / SYN-ACK / ACK). Client opens ephemeral port 52344 and establishes a reliable TCP stream to port 80 on 203.0.113.10.

  4. HTTP Exchange

    GET / HTTP/1.1 -> 200 OK (12.8 KB). Client sends GET / HTTP/1.1 (484 B) and Web Server streams back HTTP/1.1 200 OK text/html (12.8 KB).

  5. Page Rendering

    HTML parse, subresource fetch & paint. Browser parses HTML DOM, fetches linked CSS/JS assets over keep-alive, and renders the page.

HTTP security notes

  • Eavesdropping / Credential Sniffing. Plaintext HTTP headers, cookies, and form bodies can be read by any router or Wi-Fi sniffer in transit. Defense: Always upgrade to HTTPS (TLS 1.3) and enforce HSTS (Strict-Transport-Security).
  • HTTP Request Smuggling & Header Injection. Ambiguous Content-Length vs Transfer-Encoding headers trick proxies and backends into desync. Defense: Use strict RFC 9112 parsing, reject duplicate headers, or adopt HTTP/2 end-to-end.

Test yourself on HTTP

Which transport protocol does HTTP/1.1 use by default on port 80?

Answer: TCP. HTTP/1.1 relies on TCP for ordered, reliable byte delivery.

What happens before the browser sends an HTTP GET to www.example.com if the IP is unknown?

Answer: It performs a DNS lookup. The hostname must first be resolved to an IP address via DNS.

Which HTTP status code indicates a resource was successfully returned?

Answer: 200 OK. 200 OK means the request succeeded and the response body contains the representation.

Why is plain HTTP unsafe on public Wi-Fi?

Answer: Headers and cookies travel in cleartext. HTTP has no encryption layer, exposing session tokens and passwords to sniffers.

Which HTTP method is idempotent and retrieves a resource without modifying server state?

Answer: GET. GET requests only retrieve representations and are safe/idempotent.
