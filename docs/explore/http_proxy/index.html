HTTP Proxy (HTTP Forward Proxy & CONNECT Tunnel): how it works, step by step

What is HTTP Proxy?

An HTTP forward proxy relays client traffic to external servers. For HTTPS, the client sends an HTTP CONNECT host:443 request so the proxy opens a raw opaque TCP tunnel for end-to-end TLS.

How does HTTP Proxy work, step by step?

  1. TCP to Proxy

    Connect to proxy :3128. Client opens TCP session to forward proxy 192.0.2.80:3128.

  2. HTTP CONNECT Tunnel

    CONNECT example.com:443 -> 200 Connection Established. Proxy opens TCP to 203.0.113.10:443 and replies 200 Connection Established.

  3. End-to-End TLS Inside Tunnel

    Proxy forwards encrypted TLS bytes blindly. Client performs TLS 1.3 handshake directly with origin through the blind TCP tunnel.

Is HTTP Proxy secure? Common attacks and defenses

  • Open Proxy Abuse & SSRF. Misconfigured proxies let external attackers bounce traffic through internal corporate networks. Defense: Require Proxy-Authorization and restrict CONNECT destination ports to 443.

Frequently asked questions about HTTP Proxy

Which HTTP method asks a forward proxy to open a TCP tunnel for HTTPS?

Answer: CONNECT. CONNECT host:port establishes a transparent TCP tunnel through an HTTP proxy.

What status code does a proxy return when a CONNECT tunnel succeeds?

Answer: 200 Connection Established. 200 signals the tunnel is ready for raw TLS bytes.

Can a standard CONNECT proxy read your HTTPS payload without installing a root CA on your device?

Answer: No, TLS encrypts end-to-end between client and origin. Without TLS-interception CA trust, the proxy only forwards opaque encrypted bytes.
