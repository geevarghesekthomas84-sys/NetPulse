DNS (Domain Name System): how it works, step by step

DNS translates human-readable domain names into IP addresses using a globally distributed, hierarchical tree of root, TLD, and authoritative nameservers backed by TTL-based caching.

Open the interactive DNS animation to watch each packet move and inspect its headers.

DNS explained simply

DNS is the internet’s phonebook: you ask for "example.com" and it walks from the country directory (root) to the city book (.com) to find the exact street number (203.0.113.10).

DNS at a glance

Default port53
TransportUDP (queries), TCP (zone transfers / >512B)
Data formatBinary DNS Wire Format (Header + QNAME labels + RRs)
Common methodsA, AAAA, CNAME, MX, NS, TXT, PTR, SRV

Specifications: RFC 1034: Domain Names - Concepts and Facilities; RFC 1035: Domain Names - Implementation and Specification.

Devices in the DNS exchange

  • Client (host, 192.168.1.10)
  • Recursive 8.8.8.8 (dns server, 8.8.8.8)
  • Root (.) (dns server, 198.41.0.4)
  • .com TLD (dns server, 192.5.6.30)
  • Authoritative NS (dns server, 198.51.100.53)

How DNS works, step by step

  1. Stub Query

    Client sends recursive query to 8.8.8.8. OS stub resolver checks local cache, misses, and sends a UDP/53 recursive query (RD=1).

  2. Root Referral

    Root server refers to .com TLD. Root nameserver (a.root-servers.net) responds with NS delegation for the .com top-level domain.

  3. TLD Referral

    .com TLD refers to example.com NS. .com TLD nameserver returns the authoritative nameserver IP 198.51.100.53.

  4. Authoritative Answer

    Authoritative NS returns A record + TTL. Authoritative server returns A 203.0.113.10 with AA=1 and TTL=300 seconds.

  5. Cache & Reply

    Resolver caches & replies to Client. Recursive resolver caches the answer for 300s and delivers it to the client.

  2. DNS from 8.8.8.8 to 198.41.0.4: Iterative query A api.example.com (RD=0) (75 bytes)
  3. DNS from 198.41.0.4 to 8.8.8.8: Referral: .com TLD NS -> 192.5.6.30 (118 bytes)
  4. DNS from 8.8.8.8 to 192.5.6.30: Iterative query A api.example.com (75 bytes)
  5. DNS from 192.5.6.30 to 8.8.8.8: Referral: example.com NS -> 198.51.100.53 (124 bytes)
  6. DNS from 8.8.8.8 to 198.51.100.53: Iterative query A api.example.com (75 bytes)
  7. DNS from 198.51.100.53 to 8.8.8.8: Authoritative answer (AA=1): A 203.0.113.10 (TTL 300s) (91 bytes)
  8. DNS from 8.8.8.8 to 192.168.1.10: Standard query response 0x7c21 A 203.0.113.10 (TTL 300s) (91 bytes)

DNS security notes

  • DNS Cache Poisoning. An attacker races spoofed UDP replies with guessed transaction IDs to inject rogue IP records into a resolver cache. Defense: Use DNSSEC cryptographic signatures, source port randomization, and DoH/DoT.
  • DNS Amplification DDoS. Spoofing a victim’s source IP in small ANY/TXT queries triggers huge responses directed at the victim. Defense: Deploy BCP 38 egress filtering and Response Rate Limiting (RRL) on resolvers.

Test yourself on DNS

Which port and transport protocol does standard DNS use for short queries?

Answer: UDP 53. DNS uses UDP port 53 for low-latency single-packet queries, falling back to TCP 53 for large responses.

What does the TTL value in a DNS record control?

Answer: How long resolvers may cache the record. Time To Live in DNS tells caches how many seconds to store the record before re-querying.

Which DNS server sits at the very top of the hierarchy?

Answer: Root server (.). Root nameservers answer referrals for top-level domains like .com, .org, and .net.

Which DNS record type maps a domain name to an IPv6 address?

Answer: AAAA. AAAA ("quad-A") records store 128-bit IPv6 addresses.

What is the difference between a recursive query and an iterative query?

Answer: Recursive asks the server to return the final answer; iterative may return referrals. Stub clients send recursive queries (RD=1) to 8.8.8.8, which then sends iterative queries to root/TLD/auth.
