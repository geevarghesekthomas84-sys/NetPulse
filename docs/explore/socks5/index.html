SOCKS5 (SOCKS Protocol Version 5): how it works, step by step

SOCKS5 is a protocol-agnostic session proxy (port 1080) capable of relaying any TCP or UDP traffic (used by SSH dynamic port forwarding and Tor) without understanding HTTP.

Open the interactive SOCKS5 animation to watch each packet move and inspect its headers.

SOCKS5 explained simply

SOCKS5 is a universal courier pipe: you tell it the final IP and port, and it passes any kind of TCP or UDP packets through without caring what app created them.

SOCKS5 at a glance

TransportTCP / UDP Associate
Data formatBinary Greeting + Auth + Relay Header
Common methodsMethod Negotiation, Username/Password Auth, CONNECT, BIND, UDP ASSOCIATE

Specifications: RFC 1928: SOCKS Protocol Version 5.

Devices in the SOCKS5 exchange

  • Client (host, 192.168.1.10)
  • Proxy Server (proxy, 192.0.2.80)
  • Origin Server (web server, 203.0.113.10)

How SOCKS5 works, step by step

  1. Method Greeting

    Ver=5, Methods=[0x00, 0x02]. Client offers No-Auth or Username/Password; SOCKS5 server selects method.

  2. CONNECT Request

    CMD=0x01 Dst=example.com:443. Client asks SOCKS5 proxy to connect to domain/IP on port 443; proxy replies Succeeded (0x00).

  3. Transparent Relay

    Arbitrary TCP/UDP payload relayed. All subsequent bytes pass transparently between client and target origin.

What SOCKS5 looks like on the wire

This is the packet sequence NetPulse replays for a typical SOCKS5 exchange. Open the animation to inspect each one.

  1. SOCKS5 from 192.168.1.10 to 192.0.2.80: Client Greeting: Ver=5, NMethods=2 (NoAuth, User/Pass) (64 bytes)
  2. SOCKS5 from 192.0.2.80 to 192.168.1.10: Method Selection: 0x00 (Accepted) (60 bytes)
  3. SOCKS5 from 192.168.1.10 to 192.0.2.80: CONNECT example.com:443 (ATYP=Domain) (86 bytes)
  4. TCP from 192.0.2.80 to 203.0.113.10: Proxy -> Origin [SYN] Port 443 (66 bytes)
  5. SOCKS5 from 192.0.2.80 to 192.168.1.10: Reply: Succeeded (0x00) (70 bytes)
  6. TLS from 192.168.1.10 to 203.0.113.10: Relayed Application Stream (420 bytes)

SOCKS5 security notes

  • Unencrypted SOCKS5 Credentials. RFC 1929 username/password subnegotiation sends credentials in plaintext unless wrapped inside SSH/TLS. Defense: Tunnel SOCKS5 inside SSH (`ssh -D 1080`) or TLS.

Test yourself on SOCKS5

Which default port does SOCKS5 use?

Answer: 1080. IANA assigned port 1080 to SOCKS.

Which feature does SOCKS5 add over SOCKS4?

Answer: UDP Associate, IPv6, and authentication. SOCKS5 added UDP relay, IPv6 addressing, domain name resolution, and authentication.

Which SSH flag spins up a local SOCKS5 proxy tunnel?

Answer: ssh -D. `ssh -D 1080` starts dynamic SOCKS5 forwarding over the encrypted SSH tunnel.
